# Власний сайт онлайн-результатів

OrientPyx лише надсилає результати, а показує їх глядачам окремий сайт. Це відкритий проєкт того самого автора:
**[o-results](https://github.com/VadymKolesnyk/o-results)** на GitHub. Його можна розгорнути
самостійно й безкоштовно: власна онлайн-база в Supabase і власна копія сайту на GitHub Pages. Програмувати не
треба: усе робиться в браузері, приблизно за пів години.

```
OrientPyx ──запис (секретний ключ)──▶ Supabase ◀──читання (публічний ключ)── сайт ◀── глядачі
```

- **Supabase** — онлайн-база. OrientPyx кожні кілька секунд записує туди результати.
- **Сайт** — сторінка для глядачів. Він читає ту саму базу й оновлюється сам. Один сайт обслуговує всі ваші
  змагання: кожні мають власне посилання `…/#/<slug>/d1`.

Якщо сайт уже підтримує хтось інший (федерація, клуб), розгортати нічого не треба: попросіть у нього адресу
проєкту Supabase, секретний ключ і адресу сайту й переходьте одразу до [кроку 3](#connect).

Знадобиться обліковий запис на [GitHub](https://github.com) і на [Supabase](https://supabase.com) (туди можна
увійти через GitHub). Власний домен — за бажанням.

## Крок 1. Створіть онлайн-базу (Supabase) {#supabase}

1. Увійдіть на [supabase.com](https://supabase.com) і натисніть «New project». Назва — будь-яка, «Region» —
   найближчий (наприклад, Frankfurt). Пароль бази запишіть, хоча для OrientPyx він не потрібен. Безкоштовного
   тарифу (Free) досить.
2. Коли проєкт створиться, відкрийте ліворуч «SQL Editor» → «New query».
3. Відкрийте файл [`online-db/schema.sql`](https://github.com/VadymKolesnyk/o-results/blob/master/online-db/schema.sql),
   скопіюйте його повністю, вставте в редактор і натисніть «Run». Має з'явитися «Success». Скрипт створює
   таблиці для змагань, днів, груп, результатів і команд естафет. Читати їх може будь-хто, а записувати — лише
   той, хто має секретний ключ.
4. Бажано, хоч і не обов'язково: щоб сторінка глядача оновлювалася одразу, а не раз на 10 секунд, виконайте
   там само ще один запит:

    ```sql
    alter publication supabase_realtime add table public.results;
    ```

!!! warning "Скрипт створює базу наново"
    `schema.sql` спершу видаляє таблиці, якщо вони вже є, разом з усіма опублікованими результатами. Запускайте
    його лише на новій базі. Щоб доповнити наявну базу (наприклад, додати таблицю естафет), виконайте тільки
    потрібний блок, описаний у кінці файлу.

### Ключі {#keys}

Відкрийте «Project Settings → API Keys». Адресу проєкту показує вікно «Connect» (кнопка вгорі сторінки
проєкту).

| Що | Як виглядає | Куди вписати |
|---|---|---|
| Адреса проєкту (Project URL) | `https://abcdefgh.supabase.co` | на сайт і в OrientPyx |
| Публічний ключ («Publishable key») | `sb_publishable_…` | лише на сайт |
| Секретний ключ («Secret key», натисніть, щоб показати) | `sb_secret_…` | лише в OrientPyx |

У старіших проєктах ту саму роль виконують ключі `anon` (публічний) і `service_role` (секретний): це довгі
рядки, що починаються з `eyJ`. Вони теж працюють, але Supabase відмовляється від них до кінця 2026 року, тож для
нового налаштування беріть нові ключі.

!!! danger "Секретний ключ — лише в OrientPyx"
    Секретний ключ дає повний доступ до бази. Вводьте його тільки в OrientPyx: не додавайте його в налаштування
    GitHub, не пересилайте й не публікуйте. Усе, що вписано в налаштування сайту, може побачити будь-який глядач.

## Крок 2. Розгорніть сайт для глядачів (GitHub Pages) {#site}

1. Відкрийте [github.com/VadymKolesnyk/o-results](https://github.com/VadymKolesnyk/o-results) і
   натисніть «Fork» → «Create fork». У вашому обліковому записі з'явиться копія проєкту. Папка `Orientir` у ній
   — старий окремий публікатор, OrientPyx він не потрібен.
2. Підключіть сайт до своєї бази. У копії відкрийте «Settings → Secrets and variables → Actions» → вкладку
   «Variables» і через «New repository variable» додайте дві змінні:
    - `VITE_SUPABASE_URL` — адреса проєкту;
    - `VITE_SUPABASE_ANON_KEY` — **публічний** ключ (`sb_publishable_…` або `anon`).

    Без цих змінних сайт читає базу автора проєкту, і ваших результатів на ньому не буде.

3. Виберіть адресу сайту. Проєкт налаштований на домен автора, тож один із двох варіантів обов'язковий:

    === "Без власного домену"

        Сайт буде за адресою `https://<ваш-логін>.github.io/o-results/`.

        1. Відкрийте файл `web/vite.config.ts`, натисніть олівець («Edit this file»), замініть рядок
           `base: '/',` на `base: '/o-results/',` і натисніть «Commit changes». Якщо ви перейменували
           копію, пишіть її назву.
        2. Видаліть файл `web/public/CNAME` (меню «…» → «Delete file») — у ньому домен автора.

    === "Власний домен"

        Сайт буде за адресою вашого домену, наприклад `https://results.myclub.org/`. Рядок `base: '/'` у
        `web/vite.config.ts` лишається як є.

        1. Замініть домен у файлі `web/public/CNAME` на свій.
        2. У налаштуваннях DNS домену створіть запис, що веде на `<ваш-логін>.github.io`. Як саме, описує
           [інструкція GitHub](https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site).
        3. Після кроку 5 впишіть домен у «Settings → Pages» → «Custom domain», а коли перевірка пройде,
           увімкніть «Enforce HTTPS».

4. «Settings → Pages» → «Build and deployment» → «Source»: виберіть «GitHub Actions».
5. Відкрийте вкладку «Actions». У копії проєкту вони спершу вимкнені — натисніть «I understand my workflows, go
   ahead and enable them». Потім ліворуч виберіть «Deploy web to GitHub Pages» → «Run workflow» → «Run
   workflow». За хвилину-дві збірка позеленіє, а в «Settings → Pages» з'явиться адреса сайту.
6. Відкрийте адресу сайту. Має з'явитися сторінка «Не вказано змагання»: так і має бути, бо змагань у базі ще
   немає.

!!! note "Змінили змінні — перезапустіть збірку"
    Адресу бази й ключ сайт отримує під час збірки. Тому після зміни змінних (пункт 2) знову запустіть «Deploy web
    to GitHub Pages» (пункт 5). Після кожної зміни файлів у папці `web` збірка запускається сама.

## Крок 3. Підключіть OrientPyx {#connect}

Відкрийте «Файл → Налаштування» → блок «Онлайн-результати (Supabase)» і заповніть поля:

- «URL проєкту Supabase» — адреса проєкту (`https://abcdefgh.supabase.co`);
- «Service-role ключ (секретний)» — секретний ключ (`sb_secret_…` або `service_role`);
- «Публічний URL сайту глядача» — адреса сайту з кроку 2, наприклад
  `https://<ваш-логін>.github.io/o-results/`;
- «Інтервал публікації (с)» — як часто надсилати результати.

Натисніть «Зберегти підключення». Ключі діють для всіх змагань на цьому комп'ютері, а на інших комп'ютерах їх
треба вводити окремо.

## Крок 4. Перевірте {#check}

1. Відкрийте змагання з учасниками й результатами. Для проби підійде демо [Кубок міста](../demo/demo-kubok.opyx).
2. Відкрийте «Результати → Онлайн-результати», задайте «Ідентифікатор (slug) у посиланні» і натисніть «Старт
   публікації».
3. У «Журналі» має з'явитися рядок «День 1: учасників …, результатів …» без помилок.
4. Клацніть посилання в блоці «Посилання для глядачів»: сайт покаже назву змагань, групи й таблицю результатів.

Як налаштувати колонки, публікувати інші дні й що не потрапляє на сайт, описано в розділі
[Онлайн-результати](monitor-online.md#online).

## Якщо не працює {#troubleshooting}

| Що видно | Причина | Що зробити |
|---|---|---|
| У журналі «Сервер відхилив ключ доступу…» | У програмі вказано не секретний ключ (наприклад, публічний) або його скопійовано не повністю | Скопіюйте секретний ключ ще раз ([крок 1](#keys)) і натисніть «Зберегти підключення» |
| У журналі «Сервер відхилив дані — можливо, структура таблиць не збігається» | `schema.sql` не виконано, або базу створено для старішої версії | На новій базі виконайте `schema.sql`, на наявній — блоки з кінця файлу, яких бракує |
| У журналі «Увага: на сервері немає таблиці relay_teams…» | Базу створено ще до появи естафет | Виконайте блок `relay_teams` з кінця `schema.sql` |
| У журналі «Увага: у таблиці results на сервері немає колонки extra…» | Базу створено ще до додаткових колонок (колонки плагінів, додаткові поля) | У «SQL Editor» виконайте `alter table public.results add column if not exists extra jsonb;` |
| У журналі помилок немає, але сайт пише «Не вдалося завантажити результати» або показує чужі змагання | Сайт читає іншу базу: змінних немає, або після їх зміни збірку не перезапустили | Перевірте змінні ([крок 2](#site), пункт 2) і перезапустіть збірку |
| Сайт відкривається білою сторінкою | `base` у `web/vite.config.ts` не відповідає адресі сайту | `'/o-results/'` для адреси на `github.io`, `'/'` для власного домену |
| Посилання з програми ведуть не туди | Неправильний «Публічний URL сайту глядача» | Вставте адресу, яку показує «Settings → Pages» |
| Нові результати з'являються із затримкою до 10 с | Миттєве оновлення не ввімкнено | Виконайте запит із [кроку 1](#supabase), пункт 4 |

!!! warning "Безкоштовний проєкт Supabase засинає"
    Supabase призупиняє безкоштовний проєкт, до якого тиждень ніхто не звертався. Поки проєкт призупинений,
    публікація не проходить, а сайт порожній. За день-два до змагань відкрийте проєкт на supabase.com і, якщо його
    призупинено, відновіть кнопкою на сторінці проєкту. Дані при цьому зберігаються, а відновлення займає кілька
    хвилин.

## Оновіть сайт {#update}

Ваша копія сама не оновлюється. Коли в [проєкті](https://github.com/VadymKolesnyk/o-results) з'являються
зміни (наприклад, сайт навчився показувати нові дані з OrientPyx), відкрийте свою копію на GitHub і натисніть
«Sync fork» → «Update branch». Сайт перезбереться сам; якщо ні, запустіть збірку вручну ([крок 2](#site),
пункт 5).

Якщо GitHub повідомляє про конфлікт і пропонує лише «Discard commits», погодьтеся, а потім повторіть зміни
адреси з [кроку 2](#site), пункт 3. Якщо з оновленням змінився `online-db/schema.sql`, увесь файл не
перезапускайте: виконайте лише блок для наявної бази з його кінця.
