# Налагодження

Що робити, коли плагін не з'являється, не завантажується, дає помилку або рахує не те, що ви очікували: де
шукати причину, як запустити програму з вихідного коду з вашим плагіном і як під'єднати налагоджувач.

## Плагін не з'явився або «Не завантажено» {#load-errors}

Плагіни читаються лише під час запуску програми. Відкрийте «Плагіни → Керування плагінами…» (меню доступне,
коли відкрито змагання).

![Сторінка «Плагіни»](../shots/plugins.png){ .shot }

Під назвою кожного плагіна — папка, з якої його завантажено. Плагін, що не завантажився, показано окремим рядком
із червоним текстом «Не завантажено: …» і шляхом до файлу; перемикача «Увімкнено» в нього немає.

**Плагіна немає в списку взагалі** — програма його не знайшла:

- DLL має лежати як `<папка плагінів>/<Назва>/<Назва>.dll`, назва папки точно дорівнює назві DLL, без зайвого
  рівня вкладеності;
- програму не перезапустили після копіювання;
- плагін покладено в іншу папку плагінів: у встановленої програми й у запущеної з вихідного коду папки
  різні. Відкривайте потрібну кнопкою «Відкрити папку плагінів» з тієї самої програми.

**«Не завантажено: …»** — програма знайшла файл, але не змогла його завантажити. Текст причини — англійською, від
.NET або від завантажувача:

| Повідомлення | Що виправити |
|---|---|
| `No public class implementing IOrientPyxPlugin.` | клас плагіна має бути `public`, не `abstract`, з конструктором без параметрів |
| `The plugin id is empty.` | заповніть перший параметр `PluginInfo` |
| `Needs plugin API 2, the application provides 1.` | `MinApiVersion` більша за версію API програми — оновіть програму або зменшіть `MinApiVersion` |
| `Discipline … has an empty id.` | `Discipline.Id` порожній |
| `Discipline id '…' is registered twice.` | два види змагань плагіна з однаковим `Id` |
| `A field key is required.` | порожній ключ в `AddParticipantField` |
| `Could not load file or assembly …` | бракує сторонньої бібліотеки (скопіюйте всю папку з `artifacts/plugins/<Назва>`) або плагін зібрано не для .NET 10 |
| будь-що інше | виняток у вашому `Info` чи `Register` — його повідомлення |

Те саме записується в журнал дій рядком `Plugin not loaded (<id>): <шлях>: <причина>`.

**Плагін є, але його виду змагань немає в списку «Вид змагань»:**

- плагін не ввімкнено — позначте «Увімкнено»;
- інший плагін (або вбудований вид змагань) уже має такий `Discipline.Id` — ваш пропущено. Це видно лише в журналі
  дій: `Plugin '<id>': discipline '<id>' skipped (duplicate id or no built-in '…').`

**Зміни в коді не діють:**

- програму не перезапускали — гарячого перезавантаження DLL немає;
- у папці плагінів лишилася стара копія з тим самим `PluginInfo.Id` в іншій підпапці, і діє та, що далі за абеткою
  (див. [Поширення і версії](sharing.md));
- поки OrientPyx працює, Windows не дає перезаписати завантажену DLL — закрийте програму перед копіюванням. Якщо
  відкрито два вікна OrientPyx, друге не зможе оновити стандартні плагіни й запише в журнал
  `Plugin file not updated: …`.

## Помилки під час роботи {#runtime-errors}

Програма захищає кожен виклик коду плагіна. Якщо правило кинуло виняток:

- для цього виклику використовується відповідь вбудованої основи (для `AdjustTime` — час без змін; повна таблиця —
  у [Довіднику API](api.md#errors));
- виняток записується в журнал дій;
- над сторінкою з'являється банер «Плагін «<id>» дав помилку — результати пораховано за правилами «<основа>».
  Подробиці — у журналі дій.» Банер показується один раз за сеанс для кожного плагіна: якщо його закрити, він
  не з'явиться знову до перезапуску програми, навіть коли помилки тривають.

!!! warning "Поки є банер, результати рахуються не за вашими правилами"
    Принаймні частина результатів порахована за правилами основи. Не друкуйте й не публікуйте протоколи, доки не
    знайдете причину в журналі.

Виняток у лямбдах колонки (`Value`, `Problem`) не дає ні банера, ні запису в журналі — клітинка просто порожня.
Такі помилки шукайте налагоджувачем.

## Журнал дій {#activity-log}

Журнал — текстовий файл, новий на кожен запуск програми, з ім'ям за датою й часом запуску:

- поки змагання не відкрито — у `events/logs/` у папці даних програми (там само, де папка `plugins`);
- коли змагання відкрито — у підпапці `logs` папки цього змагання;
- на станції «Спільної роботи» — у `logs/<хост>-<змагання>/` у папці даних програми.

Де лежать папки змагань, видно в «Файл → Налаштування» → «Шляхи даних» → «Папка змагань».

Помилка плагіна в журналі виглядає так:

```
[14:05:31.218] ERROR  Plugin 'handicap' (handicap.set-course.AdjustTime) failed; using 'SetCourse' — NullReferenceException: …
System.NullReferenceException: …
   at AgeHandicap.HandicapSetCourse.AdjustTime(AdjustContext ctx) in …\AgeHandicapPlugin.cs:line 42
   …
```

Тут видно ідентифікатор плагіна, вид змагань, правило (`AdjustTime`), основу, яка рахувала замість нього, тип
винятку і стек викликів. Номери рядків є, коли поруч із DLL лежить `.pdb`.

Окрім помилок, у журнал на початку кожного запуску пишеться, які плагіни завантажено (`Plugin '<id>' <версія>
from <папка>`), а також коли плагін вмикають і вимикають.

## Запуск програми з вихідного коду {#run-from-source}

Найзручніше розробляти плагін, запускаючи саму програму з того самого репозиторію:

```bash
dotnet build plugins/OrientPyx.Plugins.sln
dotnet run --project src/OrientPyx.Presentation
```

Програма, зібрана в конфігурації Debug, під час кожного запуску сама копіює все з `artifacts/plugins` у свою папку
плагінів — файли, яких там немає або які там старіші. Тому цикл простий: змінили код → зібрали → перезапустили
програму. Збирати можна й тоді, коли програма працює: `artifacts/plugins` вона не блокує.

Така програма тримає свої дані окремо від встановленої — поруч зі своїм exe
(`src/OrientPyx.Presentation/bin/Debug/net10.0/`): папки `data`, `events`, `plugins`. Змагань там спочатку немає —
імпортуйте демо, наприклад [demo-kubok](../demo/demo-kubok.opyx), через «Файл → Імпорт змагань…»: подвійне
клацання по файлу відкриє його у встановленій програмі, а не в цій. Ввімкніть плагін на сторінці «Плагіни» — вибір
запам'ятається для наступних запусків.

!!! note "Видаляйте плагін в обох місцях"
    Щоб прибрати плагін із такої програми, видаліть його і з папки плагінів, і з `artifacts/plugins` — інакше під
    час наступного запуску його буде скопійовано знову.

## Налагоджувач {#debugger}

**Програма з вихідного коду.** Відкрийте `OrientPyx.sln` у Visual Studio або Rider, зробіть
`OrientPyx.Presentation` проєктом запуску і запустіть налагодження. Відкрийте файл свого плагіна (він в іншому
рішенні — просто відкрийте `.cs`) і поставте точки зупину: `.pdb` скопійовано разом із DLL, тож налагоджувач їх
прив'яже.

**Встановлена програма.** Зберіть плагін у Debug, скопіюйте папку разом із `.pdb` у папку плагінів, запустіть
OrientPyx і під'єднайтеся до процесу `OrientPyx`: у Visual Studio — «Debug → Attach to Process…», у Rider — «Run →
Attach to Process…». Потім відкрийте файл плагіна й поставте точки зупину.

!!! tip "Під'єднатися з самого початку (лише Windows)"
    Щоб зупинитися вже в `Register`, додайте на його початку `System.Diagnostics.Debugger.Launch();` — Windows
    запропонує вибрати налагоджувач. Не забудьте прибрати цей рядок, перш ніж передавати плагін іншим.

Коли програма викликає правила:

| Правило | Щоб викликати |
|---|---|
| `Info`, `Register`, `Name`, `Settings`, `Columns`, `AwardsRanks` | запуск програми |
| `ResolveStart`, `EvaluateFinish`, `AdjustTime`, `Rank` | будь-який показ результатів: таблиця дня на сторінці «Учасники», «Результати → Протоколи результатів», журнал «Зчитка на фініші» |
| `BuildSplits` | виберіть рядок у журналі «Зчитка на фініші» (для основ «За вибором за часом» і «Рогейн» — ще й під час підрахунку балів) |
| `Value`, `Problem` колонок | показ колонки в таблиці дня чи протоколі |

Результати рахуються щоразу, коли їх показують, тож точка зупину в `AdjustTime` спрацює багато разів — по разу
на кожен OK-результат при кожному оновленні сторінки. Ставте умовні точки зупину (наприклад, за
`ctx.Participant.FullName`).

## Перевірка без програми

Власну логіку плагіна (обчислення штрафу, роботу з таблицею через `RangeTable`, `Age`, `CourseMatcher`) зручно
перевіряти модульними тестами: типи SDK — звичайні класи, `ResultRow` і `SettingValues` мають публічні
конструктори. А от виклики `base.…` працюють лише всередині програми — без неї вони кидають
`InvalidOperationException`. Як стандартні плагіни перевіряються на справжньому підрахунку результатів, видно в
тестах репозиторію: `tests/OrientPyx.Tests/Core/PluginDisciplineTests.cs`.
