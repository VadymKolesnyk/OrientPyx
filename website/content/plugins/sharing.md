# Поширення і версії

Як передати готовий плагін іншим організаторам, як він переживає оновлення програми і що відбувається зі
змаганнями, які відкривають без потрібного плагіна.

## Як передати плагін іншим {#share}

1. Зберіть плагін у конфігурації Release:

    ```bash
    dotnet build plugins/OrientPyx.Plugins.sln -c Release
    ```

2. Заархівуйте **папку** `artifacts/plugins/<Назва>` цілком: `<Назва>.dll`, `<Назва>.deps.json`,
   `<Назва>.runtimeconfig.json`, сторонні бібліотеки, якщо є. Файл `<Назва>.pdb` необов'язковий, але з ним у
   журналі дій видно номери рядків, де сталася помилка.
3. Отримувач у OrientPyx відкриває «Плагіни → Керування плагінами…» → «Відкрити папку плагінів», закриває
   програму і розпаковує архів туди так, щоб вийшло `plugins/<Назва>/<Назва>.dll`.
4. Запускає OrientPyx і позначає «Увімкнено» біля вашого плагіна.

!!! warning "Перевірте вкладеність папок"
    Програма шукає лише `<папка плагінів>/<Назва>/<Назва>.dll`, де назва папки точно дорівнює назві DLL.
    Плагін у `plugins/<Назва>/<Назва>/<Назва>.dll` (зайвий рівень після розпакування) або просто DLL у
    корені папки плагінів не буде знайдено — і на сторінці «Плагіни» його не буде навіть з помилкою.

Плагін — це код, що виконується з усіма правами програми. Передавайте разом із ним вихідний код або посилання на
нього, щоб отримувач міг переконатися, що плагін робить лише те, що обіцяє.

!!! note "На кожному комп'ютері"
    Результати рахує кожна копія програми сама, тож плагін потрібен на кожному комп'ютері, де відкривають
    змагання з його видом змагань: на хості й усіх станціях «Спільної роботи», на комп'ютері, куди переносять
    змагання файлом `.opyx`. І версія має бути однакова — інакше різні комп'ютери покажуть різні результати.

## Сторонні бібліотеки

Плагін може користуватися пакетами NuGet: додайте `PackageReference` у свій `.csproj`. Під час збирання бібліотеки
копіюються в `artifacts/plugins/<Назва>/` поруч із DLL плагіна, а `<Назва>.deps.json` описує, звідки їх брати.
Програма завантажує кожен плагін в окремий контекст і бере його залежності з його ж папки, тож два плагіни можуть
мати різні версії однієї бібліотеки. Передавайте папку цілком.

Посилатися можна лише на SDK (`OrientPyx.Plugins.Sdk` — його вже підключає `plugins/Directory.Build.props`) і на
сторонні пакети. На інші проєкти програми (`OrientPyx.BusinessLogic` тощо) посилатися не можна: вони не є
частиною API і змінюються без попередження. SDK завжди береться з самої програми — копія в папці плагіна
ігнорується.

!!! tip "Назва продукту у властивостях файлу"
    Спільний `plugins/Directory.Build.props` задає для всіх проєктів `<Product>OrientPyx</Product>` і
    `<Company>OrientPyx</Company>` — це потрібно стандартним плагінам. Для свого плагіна перевизначте їх у своєму
    `.csproj`, щоб у властивостях DLL стояло ваше ім'я.

## Версії {#versions}

У плагіна дві різні версії:

- **версія самого плагіна** — `PluginInfo.Version`, довільний рядок, який видно на сторінці «Плагіни». Підвищуйте
  її з кожною зміною, щоб організатори бачили, яка в них копія;
- **версія API** — `ApiVersion.Current` у програмі (зараз 2) і `PluginInfo.MinApiVersion` у плагіні (за
  замовчуванням 1). Якщо `MinApiVersion` більша за версію API програми, плагін не завантажується, а на сторінці
  «Плагіни» пишеться, якої версії він потребує.

Збірка SDK має явно задану версію `1.0.0.0`, яка не залежить від версії програми: від першої версії з плагінами
(0.7.0) і досі всі випуски OrientPyx містять ту саму збірку SDK `1.0.0.0`. Тому плагін, зібраний проти SDK з
однієї версії програми, завантажується в інших. Правило SDK: нове лише **додається** — версія API 2 (імпорт
додаткових полів і звіти) нічого не забрала з версії 1, і плагін для API 1 працює без змін; несумісна зміна означала б
нову мажорну версію збірки. Хто користується новим із версії 2, ставить `MinApiVersion: 2` — старіша програма тоді
не завантажить плагін і напише, якої версії API він потребує.

!!! warning "Нове в SDK з'являється з новими версіями програми"
    Якщо ваш плагін користується типом чи методом SDK, якого ще немає в старішій програмі (наприклад, `SiCard`
    з'явився у версії 0.7.3), у такій програмі плагін або не завантажиться, або дасть помилку під час виклику —
    і програма порахує результат за правилами основи. Збирайте плагін проти тегу найстарішої версії, яку
    підтримуєте (`git checkout v0.7.16`), або попросіть користувачів оновити програму.

## Що буде після оновлення програми

- Папка плагінів лежить у папці даних, а не в папці програми, тож оновлення її не чіпають: ваші плагіни і
  вибір «Увімкнено» лишаються.
- Стандартні плагіни оновлюються самі: під час запуску програма копіює їх файли зі свого пакета в папку
  плагінів, якщо файлу там немає або він старіший.
- Ваш плагін продовжує працювати, поки версія API та сама (див. вище).

!!! warning "Не називайте свою папку як стандартний плагін"
    Папки `MissedControlPenalty` і `WeightedRelay` програма оновлює зі свого пакета, щойно файл у пакеті
    новіший. Власна збірка в такій папці зникне з першим оновленням.

## Той самий ідентифікатор у двох папках

Програма переглядає підпапки папки плагінів за абеткою. Якщо два плагіни мають однаковий `PluginInfo.Id`, діє
той, чия папка **далі за абеткою**, — без жодного повідомлення. Так буває, коли стара копія лишилася під іншою
назвою папки (`AgeHandicap` і `AgeHandicap-new`). Перевірте шлях, який сторінка «Плагіни» показує під назвою
плагіна, і видаліть зайві копії.

Ідентифікатори видів змагань теж мають бути унікальні: якщо два плагіни оголошують однаковий `Discipline.Id`
(або назву вбудованого виду змагань), діє той, що завантажився першим, а другий пропускається — це видно лише в
журналі дій. Тому починайте `Id` виду змагань з ідентифікатора свого плагіна.

## Змагання, що потребують плагіна {#required}

Змагання пам'ятає вид змагань кожного дня й групи за його `Id`. Якщо змагання відкрити там, де плагіна немає
або його вимкнено:

- над сторінкою з'являється банер «Потрібен плагін «…» для дисципліни … — встановіть або ввімкніть його в меню
  «Плагіни». Відмітки перевіряються як у заданому напрямку; місць, очок і розрядів немає.»;
- у списках «Вид змагань» такий день показано як «Невідома дисципліна (…) — потрібен плагін»;
- статус і час учасників видно, але місць, очок і розрядів немає;
- налаштування плагіна й значення його полів учасника не зникають. Щойно плагін встановлять і ввімкнуть,
  результати порахуються як слід.

Під час експорту змагань («Файл → Експорт змагань…») у файл `.opyx` записується `plugins.json` — перелік потрібних
плагінів (ідентифікатор, версія, види змагань). Під час імпорту (подвійне клацання по файлу `.opyx` або «Файл →
Імпорт змагань…») програма попереджає: «Змагання використовує плагіни, яких тут немає або їх вимкнено: … Імпорт
можливий, але ці дисципліни не рахуватимуться, доки плагін не встановлено.» Перевіряється лише наявність увімкненого
плагіна, не його версія.

У «Спільній роботі» станція під час підключення порівнює перелік увімкнених плагінів із хостом за
ідентифікаторами й попереджає про розбіжності. Версії не порівнюються — однакову версію на всіх комп'ютерах
забезпечте самі.
