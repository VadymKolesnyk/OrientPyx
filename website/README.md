# Сайт документації OrientPyx

Документація для користувачів програми: https://vadymkolesnyk.github.io/OrientPyx/ (лише українською).
Генератор — [MkDocs Material](https://squidfunk.github.io/mkdocs-material/), версії закріплені в
[`requirements.txt`](requirements.txt).

```
website/
  mkdocs.yml        налаштування сайту і навігація (порядок розділів — тут)
  requirements.txt  версії MkDocs і плагінів
  hooks.py          генерує «Довідник екранів» (з Help.* у uk-UA.json) і «Що нового» (з GitHub Releases)
  docs-map.yml      які сторінки описують яку частину коду — для перевірки перед релізом
  tools/affected.py що могло застаріти з останнього релізу (крок 2b у /new-version)
  content/          сторінки (Markdown); content/img — картинки, зроблені вручну (логотип, схеми)
  content/shots/    скріни програми — генеруються, у git не потрапляють
  content/demo/     демо-змагання (.opyx) для завантаження — генеруються, у git не потрапляють
  site/             зібраний сайт — у git не потрапляє
```

## Перегляд і збірка

```powershell
scripts/docs.ps1                  # живий перегляд на http://127.0.0.1:8000 (скріни рендеряться, якщо їх ще немає)
scripts/docs.ps1 -Shots           # те саме, але скріни й демо-змагання рендеряться наново
scripts/docs.ps1 -Shots -Build    # як у CI: свіжі скріни + сувора збірка (будь-яке попередження = помилка)
```

Скрипт сам створює `.venv-docs/` (потрібен Python 3) і ставить туди залежності.

## Скріни і демо-змагання

Їх робить сама програма в headless-режимі: тести `tests/OrientPyx.Tests/DocShots/` (атрибут `[DocShotFact]`,
пропускаються, доки не задано `ORIENTPYX_DOCSHOTS`). `DemoCompetitions.cs` будує вигадані змагання — дводенний
«Кубок міста» і по одному на кожен тип; `DocShotTests*.cs` відкриває сторінки й знімає вікно 1280×800 у
`content/shots/<назва>.png` (з описом у `shots/manifest.json`). `DocShooter` уміє обрізати знімок до блоку
(`CardOfAsync`), обвести кнопки рамками з номерами, відкрити меню чи діалог.

Новий скрін: додайте виклик `ShotAsync("назва", "опис")` у відповідний сценарій, запустіть `scripts/docs.ps1 -Shots`
і посилайтеся на `../shots/назва.png`. На скріні не має бути справжніх шляхів чи імені комп'ютера — підмініть їх, як
файл зчитки на сторінці фінішу.

## Публікація

`.github/workflows/docs.yml` рендерить скріни, збирає сайт і викладає його на GitHub Pages:

- **на тег релізу** (`v*`) — тексти й скріни саме цієї версії;
- **вручну** (Actions → Docs → Run workflow) — тексти з вибраної гілки (виправлення між релізами), скріни — з
  останнього релізу, щоб на сайті не з'явилося ще не випущене.

Один раз у налаштуваннях репозиторію: Settings → Pages → Source: **GitHub Actions**.

## Як писати

Сайт — для тих, хто проводить змагання, а не для розробників.

- **Від задачі, а не від екрана.** Заголовок відповідає на «як зробити …», далі кроки по порядку.
- **Лише те, що видно в програмі.** Назви кнопок, колонок і пунктів меню — точно як в інтерфейсі, у «лапках»;
  шлях меню — через стрілку: «Старт → Жеребкування». Жодних імен класів, файлів коду чи таблиць бази.
- **Звертання на «ви»**, наказовий спосіб: «Відкрийте…», «Натисніть…».
- **Скрін на кожен важливий крок**, з підписом, що на ньому треба помітити. Скрін ілюструє текст, а не замінює його.
- **Клавіші** — `++ctrl+w++`, `++f8++` (розширення `pymdownx.keys`).
- **Примітки** — `!!! tip`, `!!! warning` для того, що легко пропустити або зіпсувати (втрата даних, неправильні результати).
- **Терміни програми**: «Бали» — бали рогейну/вибору за КП; «Очки» — рейтингові очки за місце. Типи змагань — як у
  списку програми: «Заданий напрямок», «За вибором по кількості КП», «За вибором за часом», «Рогейн», «Змішаний»,
  «Розсіювання», «Естафета».
- **Довідка «?» у програмі і сайт не мають суперечити одне одному.** Коротка версія — у `Help.*`
  (`src/OrientPyx.Localization/Resources/uk-UA.json`), повна — тут.

Виняток — розділ «Власні плагіни»: він для розробників, там доречні код і назви типів SDK.
