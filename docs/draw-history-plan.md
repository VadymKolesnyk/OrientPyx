# Жеребкування з урахуванням попередніх днів — план

> Реалізовано 2026-11-06 за цим планом; тести — `tests/OrientPyx.Tests/Core/DrawHistoryTests.cs`.

Мета: на багатоденних змаганнях жеребкування дня N має «пам'ятати» стартові позиції попередніх днів,
щоб одна людина не стартувала першою (чи останньою) два дні підряд, а в малих групах (до 5 осіб) не
виходив той самий стартовий протокол. Галочка «Враховувати попередні дні» на обох сторінках
жеребкування, за замовчуванням увімкнена.

Принцип: випадковість зберігається. Існуючий порядок (Fisher–Yates + рознесення за клубом) запускається
N разів, кожен кандидат оцінюється штрафами за історію, береться найкращий. Жорстких правил немає — коли
штраф обнулити неможливо (2 особи на 3 дні), береться мінімальний.

## 1. Модель (BusinessLogic/Models/DrawData.cs)

- `DrawHistoryEntry(int DayNumber, int Position, int GroupSize, string? PredecessorKey)` — позиція 0-based
  у групі того дня; `PredecessorKey` — ключ одиниці, що стартувала безпосередньо перед (null для першого).
- `DrawParticipant` отримує `string HistoryKey` (учасник → `ParticipantId`; естафетна команда →
  `team:<groupId>:<number>`) та `IReadOnlyList<DrawHistoryEntry> History` (необов'язкові параметри
  з типовими значеннями, щоб існуючі виклики й тести не змінювались).
- `DrawSettings.ConsiderPreviousDays { get; set; } = true` — спільне для обох сторінок (Lanes/Classic);
  відсутнє в старому JSON → true.

## 2. Сервіс (BusinessLogic/Services/StartDrawService.cs)

- `Draw(..., bool considerPreviousDays = false)` і `DrawClassic(..., bool considerPreviousDays = false)`.
- `DrawGroupOrder`: якщо прапорець увімкнений, у групі ≥ 2 одиниць і хоч хтось має історію — генерує
  `Trials = 200` кандидатів (той самий `Random`, той самий `DrawGroupOrder` з рознесенням) і повертає
  кандидата з мінімальним штрафом. Перший серед рівних, тому серед рівноцінних порядків результат лишається
  випадковим. Без історії/прапорця — поведінка побітно та сама, що зараз (той самий seed → той самий
  результат).
- Оцінка — окремий `internal static class DrawHistoryScore` (чистий, тестується напряму). Штрафи, від
  важких до м'яких (ваги — константи з коментарями):
  1. Повтор першого стартера групи (позиція 0 сьогодні і позиція 0 у будь-який попередній день, коли група
     була ≥ 2) — 1000 за кожен такий день. Те саме для останнього.
  2. Повторена пара сусідів «A одразу після B» з попереднього дня — 100 за кожну пару.
  3. Мала зміна позиції відносно останнього дня: `10 × (1 − |q − p_last|)`, де q і p — нормалізовані
     позиції (0 = перший, 1 = останній; для групи з 1 особи — 0.5).
  4. Накопичений дисбаланс: `10 × 2 × |середнє(p по всіх днях включно з сьогоднішнім) − 0.5|` — хто два
     дні стартував на початку, третього піде в кінець.
- Естафета: одиниця — команда, ключ — номер команди в групі (склад етапів може змінюватись).

## 3. Дані (CompetitionEditorService.GetDrawPrepDataAsync)

- Попередні дні = дні з `EventDay.Number` меншим за поточний (не за датою), де проставлено `StartTime`.
- Одна вибірка `GetAllParticipantDaysAsync`; для кожного попереднього дня — лінки з `GroupId` і `StartTime`,
  згруповані за групою того дня (саме тією, де учасник біг тоді), відсортовані за `StartTime`, потім за
  номером → позиція, розмір, попередник.
- Естафетні дні: одиниця — лінк етапу 1 з `RelayTeamId`; `GetRelayTeamsAsync(prevDayId)` читається лише
  коли такі лінки є; ключ `team:<groupId>:<number>`.
- Учасник без історії (новий на цей день) — порожній список, у штрафах нейтральний.
- Використовуються лише існуючі методи `IEventStore` → контракт RPC і `NetworkProtocol.Version` не
  змінюються; на станції працює через той самий роутер.

## 4. UI (Presentation)

- `DrawViewModel` і `ClassicDrawViewModel`: `[ObservableProperty] bool considerPreviousDays` (→
  `SaveSettings()`), `HasPreviousDays` (хтось із завантажених має історію) → `IsEnabled` галочки;
  коли історії нема — підказка «Немає попередніх днів зі стартами». Передається у `_draw.Draw/DrawClassic`.
- `DrawView.axaml` і `ClassicDrawView.axaml`: `CheckBox` поруч із комбо «Рознесення».
- Таблиця результатів на сторінці смуг: колонка «Попередні дні» зі значеннями виду `1/5 · 4/5`
  (позиція 1-based/розмір групи по днях); `DrawResultRowViewModel.HistoryLabel`. Форматування —
  маленький хелпер у Presentation.
- Довідка сторінки (ScreenHelp) — абзац про галочку і правила.

## 5. Локалізація (uk-UA.json + en-US.json)

`Draw.PreviousDays` («Враховувати попередні дні»), `Draw.PreviousDays.Hint` (що саме уникається),
`Draw.PreviousDays.None`, `Draw.Col.PreviousDays`, ключі довідки.

## 6. Тести (tests/OrientPyx.Tests/Core/DrawHistoryTests.cs)

1. Група з 3 осіб, день 1 = позиції 0,1,2; 100 seed'ів дня 2: жодного разу той самий перший, той самий
   останній, той самий порядок.
2. 2 особи, день 1 → день 2 завжди обернений.
3. Історія + рознесення за клубом: рознесення дотримується там, де фізично можливо.
4. Регресія: `considerPreviousDays: false` або порожня історія → результат побітно дорівнює поточному
   алгоритму з тим самим seed.
5. Три дні: середня позиція кожного прямує до середини (хто був 0 і 0 — третього дня в нижній половині).
6. `GetDrawPrepDataAsync` на `CompetitionBuilder` з 2 днями: історія заповнена (позиція, розмір,
   попередник), новий учасник без історії, естафетна команда з ключем за номером.
7. Існуючі golden-знімки результатів не зачіпаються (жеребкування не впливає на результати).
