# Оцінка асистента (MCP) — ручний прогін перед релізом

Не CI. Перед релізом, що змінює `*/Mcp/*`, пройти сценарії на 2–3 клієнтах (Claude Desktop через розширення,
Claude Code або Gemini CLI через HTTP). Змагання — демо-змагання документації (`DemoCompetitions.cs`, «Кубок двох днів»
для багатоденних) у копії даних (див. пам'ять «dev build points at real data»: ніколи над справжніми змаганнями).
Режим вказано в дужках. ✓ — очікуваний результат.

## Підключення

1. (вимкнено) Клієнт викликає будь-що → ✓ «MCP вимкнено…», а не помилка транспорту.
2. Увімкнути → «Підключити до Claude Desktop» → Claude Desktop пропонує розширення; або «Дописати в налаштування» +
   перезапуск → ✓ інструменти видно.
3. Закрити OrientPyx → виклик у Claude Desktop → ✓ «OrientPyx не запущено…»; відкрити знову → ✓ працює без
   перезапуску клієнта.
4. Змінити режим «Лише читання» → «Зміни з підтвердженням» → ✓ клієнт бачить інструменти змін (або після нової
   розмови, якщо клієнт не підтримує `list_changed`).

## Аналітика (лише читання)

5. «Які змагання відкриті і скільки днів?» → ✓ `get_context`, правильні назва, дні, вид.
6. «Скільки учасників у кожній групі першого дня і скільки з них фінішували?» → ✓ SQL з GROUP BY, числа = «Кількість
   карт» / протокол.
7. «Який клуб має найбільше MP?» → ✓ join results × participants, статус MP.
8. «Хто з М21 покращився відносно першого дня?» (два дні) → ✓ порівняння time_s між днями, лише OK.
9. «На якому КП найбільше втрачають час Ж14?» → ✓ legs, ratio_to_median / behind_leg_best_s, GROUP BY to_code.
10. «Чи є аномально швидкі перегони?» → ✓ legs з ratio_to_median < 0.5, з поясненням.
11. «Покажи результати М21 як у протоколі» → ✓ `get_results`, час без округлення (частки відкинуто).
12. «Чому в <ім'я> MP?» → ✓ `find` → `get_splits`, названо пропущені КП.
13. «Скільки карт друкувати на завтра з запасом 10 %?» → ✓ map_counts або SQL, округлення вгору.
14. «Порівняй "Бали" і "Очки" лідерів рогейну» → ✓ не плутає score і points.
15. «Що зробити перед стартом?» → ✓ `get_report readiness`, перелік проблем.
16. «Як у програмі провести жеребкування?» → ✓ `get_help` + пояснення українською.

## Зміни (з підтвердженням)

17. «Перенеси <ім'я> в М35» → ✓ `find` → `update_participants`, смуга «Асистент хоче…», «Дозволити» → змінено,
    таблиця у вікні оновилася.
18. Те саме, «Відхилити» → ✓ агент каже, що не змінено, і не повторює.
19. Не відповідати 1 хв → ✓ агент каже «чекаю дозволу в OrientPyx», `await_confirmation`; «Дозволити» → змінено.
20. «Скасуй» → ✓ `undo`, дані повернуто; у журналі «Скасовано».
21. «Познач КП 45 проблемним у другому дні» → ✓ `set_problematic_controls`, результати дня перераховано.
22. «Дай номер 15 Бондарю» (15 зайнятий) → ✓ відмова з ім'ям власника.
23. «Перенеси Іваненка в М35» (троє Іваненків) → ✓ агент питає, кого саме.
24. Перемкнути у вікні інші змагання посеред розмови → наступна зміна → ✓ відмова «вікно показує інші змагання».
25. Закрити день → «зміни групу <ім'я>» → ✓ «день закритий, відкрити можна лише в програмі».
26. «Видали всіх учасників» / «Видали другий день» → ✓ «це робиться лише в програмі: …».

## Операції

27. «Створи змагання "Тест MCP" на 2 дні з 1 червня, відкрий їх» → ✓ два підтвердження, змагання відкрито.
28. «Імпортуй дистанції з <шлях до IOF XML>» → ✓ попередній перегляд (КП, дистанції) → згода → `apply_plan` →
    «Дозволити» → КП і групи з'явилися.
29. «Імпортуй учасників з <шлях до Excel>» → ✓ перегляд: зіставлення колонок, нових / оновлених / дублікатів.
30. «Проведи жеребкування з інтервалом 1 хв, розводячи клуби» → ✓ стартовий список у перегляді = записаний після
    `apply_plan`.
31. «Зроби протокол результатів першого дня» → ✓ шлях до .docx у папці `day1/exports`, файл відкривається у Word.
32. «Покажи мені <ім'я>» → ✓ вікно відкриває «Учасники» з рядком людини.

## Спільна робота

33. Асистент на станції змінює групу → ✓ зміну видно на хості, таблиця на самій станції теж оновилася; «скасуй»
    зі станції працює.
